## Функции безопасного облачного стека (создание безопасности в облаке с нуля):  
1. **Соответствие**: Обеспечение соответствия системы нормативно-правовым требованиям и ведение журнала аудита с помощью автоматизации. Создание журнала изменений. Развертывание привил для предотвращения несанкционированных методов развертывания.
2. **Шифрование**: Конфиденциальные данные должны быть зашифрованны при передаче по сети или хренении в целевых хранилищах.
3. **Масштабирование и доступность**: облачные ресурсы должны быть рассредоточени и децентрализированны. Это улучшит производительность и устранит единую точку отказа.
4. **DLP**: Не позволять записывать какие либо личные и конфиденциальные данные в журнал или другие неавторизованные места.
5. **Защита учетных данных и других конечных точек**: не хранить учетные данные сервисов и исходные/целевые точки в памяти. Использовать собственные сервисы токенизации с минимальными привилегиями, чтобы свести к минимум масштаб потенциального ущерба. При создании учетных данных для сотрудников разработать правила IAM с отдельными конкретными политиками. Постоянно отсматривать и отслеживать изменения и применение.
6. **Кеширование**: Поддержка проектов без сохоранения состояния. Приложения никогда не должны хранить информацию в памятидольше, чем необходимо для выполнени запроса. Следовательно, в члучае сбоя одной машини запрос может быть легко перенесен на другую мащину в парке серверов приложений.

## Сетевые брандмауеры  

**Группы безопасности (SG)** и **списки контроля доступа к сети (NACL)** действуют как брандмауэри для виртуальных машин в плоскости облачной сети. SG действуют через интерфейс машинной сети (network interface, NI) и, как правило, более гибки и полезны при повседневном развертывании. SG могут быть изменены на лету, а правила распространяются на все NI в группе. SG по умолчанию ограничивают весь трайик, кроме трафика от других машин в той же SG, и разрешают весь исходящий трафик. NACL похожи, но применяются ко всей подсети и по умолчанию разрешают весь трафик.

## Журнал и мониторинг  

Сетевые журналы позволяют пользователю облака просматривать сетевой трафик на уровне своей частной облачной сети. (Журнал потоков AWS VPC, журнал потоков Azure и GCP stackdriver).  

Журналы потоков содержат большое количество информации, квлючая перечисленную далее, но не ограничиваясь ею:  
  - IPv4/IPv6 адрес отправителя и получателя;
  - порт, используемый приложением на стороне отправителя и получателя;
  - номер протокола по версии IANA;
  - количество пакетов;
  - размер в байтах;
  - время начала и окончания захвата трафика;
  - действие/состояние (был трафик разрешен правилами брандмауэра или нет);
  - ID аккаунтов;
  - ID интерфейса (логический идентификатор виртуального сетевого интерфейса);

## Журнал аудита  
Журналы аудита позволяют фиксировать и сохранять все управленческие/логические события, администрируемые в облачной среде. Для создания проверенных сред или просто поддерживания масштабируемой и устойчивой корпоративной облачной среды очень важно иметь возможность отслеживать действия сотен пользователей, которые могут взаимодействовать с облачной средой.  

Поскольку все сервисы облачных провайдеров основаны на масштабируемых API, все взаимодействия с облачной средой можно свести к API-вызовам. Журналы, создаваемые такими API-вызовами, содержат множество информации, включая следующую, но не ограничиваясь ею:  
  - тип события, имя, время и источник;
  - ID ключа доступа;
  - ID аккаунта;
  - имя пользователя;
  - область;
  - IP-адрес источника;
  - парамеры запроса;
  - элементы ответа;

Инструменты журналов аудита: AWS CloudTrail, Azure Control, GCP Cloud Audit Logging.  

## Инструменты мониторинга  
Инструменты мониторинга позволяют пользователю облака панель мониторинга для просмотра показателей и изучения поведения облачной среды с течением времени. Команды, занимающиеся безопасностью и администрированием, всегда должны стремиться к тому, чтобы система мониторинга всего стека была доступна в виде единой консоли управления.  

Некоторые важные функции, которые следует применять с этими сервисами:  
  - ежеминутный детальный мониторинг;
  - установка и запуск сигналов оповещения, когда показатели мониторинга достигают определенных пороговых значений;
  - автоматизация действий на основе сигналов оповещений;
  - создание собственных  информационных панелей с графиками и статистикой;

Файлы журналов могут быть зашифрованны.  

Инструменты: AWS CloudWatch, Azure monitor, GCP Stackdriver.
