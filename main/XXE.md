## DOCX, PPTX, XLSX

Open XML fioramt file contains:
  - Document properties;
  - Custom Defined XML;
  - Charts;
  - Embedded Code/Macros;
  - Image, Video, Sound files;
  - WordML/SpreadsheetML, etc.;
  - Comments;

Основная часть документа XML содержиться в:  
  - /word/document.xml
  - /ppt/presentaion.xml
  - /xl/workbook.xml

**Обработка XML в браузере**: https://developer.mozilla.org/ru/docs/Web/XML/Guides/Parsing_and_serializing_XML  

**Пример простого документа в XML**:  
```
<?xml version="1.0"?>

<!-- Comment -->

<PRODUCTS>
     <PRODUCT>
          <TITLE> Product #1 </TITLE>
          <PRICE> 10.00 </PRICE>
     </PRODUCT>
     <PRODUCT>
          <TITLE> Product #2 </TITLE>
          <PRICE> 20.00 </PRICE>
     </PRODUCT>
</PRODUCTS>
```
Для использования символов кириллицы нужно использовать такой заголовок:  
```
 <?xml version="1.0" encoding="windows-1251"?>
```
Если для XML документа существует файл CSS, который задает отображение каждого элемента XML, то его нужно добавить в конце XML документа:  
```
 <?xml-stylesheet type="text/css" href="Sample.css"?>
```
В результате при открытии XML-документа в браузере он будет отображён в соответствии с инструкциями, записанными в таблице стилей.  

**Атрибуты элементов**:  
 В начальный тэг элемента либо в тэг пустого элемента вы можете включить одно или несколько описаний атрибутов. Описание атрибута представляет собой пару имя - значение, например:  
```
 <PRICE type="retail">$10.55</PRICE> 
```
ИЛИ  
```
 <PRICE type="retail" /> 
```
Если XML-документ отображается с помощью таблицы стилей CSS, браузер не выводит атрибуты и их значения. Доступ к атрибутам и их значениям даёт отображение XML-документа с использованием XSL-таблицы, связывания данных или сценария.  

## Internal, external, parameter entities  
Формат определения сущности (**internal**):  
```
<!ENTITY entityname "replacement text">
```

Формат определения сущности (**external**):
```
<!ENTITY entityname [PUBLIC "public-identifier"]
        SYSTEM "system-identifier">

<!-- --->
<!ENTITY chap1 SYSTEM "chap1.xml">
<!ENTITY mypicture SYSTEM "pic01.gif" GIF>
```
Идентификатор SYSTEM должен указывать на экземпляр ресурса посредством URI, чаще всего в виде простого имени файла. PUBLIC идентификатор, если он указан, может использоваться XML-системой для генерации альтернативного URI (это обеспечивает удобный уровень косвенного доступа в системах, поддерживающих публичные идентификаторы).

Внешние (**external**) сущности можно далее классифицировать как «parsed» или «unparsed». Сущности, ссылающиеся на внешние файлы, содержащие XML, называются «parsed»; сущности, ссылающиеся на другие типы данных, обозначенные специальной нотацией, являются «unparsed». Анализатор вставляет текст, заменяющий parsed сущность, в документ во всех местах, где встречается ссылка на эту сущность. Вставка ссылки на unparsed сущность непосредственно в текст XML-документа считается ошибкой. unparsed сущности могут использоваться только в качестве значений атрибутов элементов, имеющих атрибут ENTITY. unparsed сущности чаще всего используются в XML-элементах, которые включают графические объекты в документ.

Формат записи сущности в тегах:
```
&имя_сущности;
```

**Predefined entities**:  
- <    &lt;
- >    &gt;
- &    &amp;
- '    &apos;
- "    &quot;

**Entity expansion**:  
```
<!ENTITY foobar "&f;bar"> <!ENTITY f "foo">
```
- Символьные ссылки расширяются сразу же. Они ведут себя точно так же, как если бы вы ввели соответствующий символ напрямую.
- Ссылки на символы в тексте, заменяющем другие символы, не развертываются до тех пор, пока не будет сделана ссылка на объявляемый символ. Иными словами, это допустимо во внутреннем подмножестве.
- parsed сущности допускаются в тексте документа, тогда как unparsed сущности там запрещены. unparsed сущности допускаются в атрибутах сущностей, тогда как parsed сущности там запрещены.
- Хотя в значениях атрибутов можно указывать ссылки на internal сущности, ссылка на external сущность в значении атрибута является недопустимой.
